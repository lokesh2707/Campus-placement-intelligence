# Database Design & Entity Architecture

## 1. Architectural Philosophy

The platform's database layer is built on **PostgreSQL 16** with the **pgvector** extension, managed through **Prisma ORM**. PostgreSQL was chosen for its strict relational integrity, ACID compliance, enterprise auditing capabilities, and native high-dimensional vector search support via pgvector (eliminating the need for costly third-party vector databases like Pinecone or Weaviate).

---

## 2. PostgreSQL Extensions

- `uuid-ossp`: For cryptographically secure UUIDv4 primary keys.
- `vector` (`pgvector`): For storing 384-dimensional dense vectors (generated by `all-MiniLM-L6-v2` or similar sentence-transformer embeddings) directly alongside student profiles and job postings.

## 3. High-Level Entity Relational Hierarchy

```text
  │     └── Degree

  └── Company

              └── Embedding (vector[384])
```

## 4. Comprehensive Entity Planning

### 4.1 Institutional & Academic Hierarchy

1. **College**: Root institutional tenant (multi-tenancy anchor).
   - Fields: `id`, `name`, `code`, `address`, `website`, `tier`, `createdAt`, `updatedAt`.
2. **Campus**: Physical campus locations for colleges with multiple branches.
   - Fields: `id`, `collegeId`, `name`, `location`.
3. **Department**: Academic departments (e.g., Computer Science, Mechanical).
   - Fields: `id`, `collegeId`, `name`, `code`.
4. **Degree**: Academic degrees offered (e.g., B.Tech, M.Tech, MCA).
   - Fields: `id`, `departmentId`, `name`, `durationYears`.
5. **Batch**: Academic graduation cohorts (e.g., Class of 2026).
   - Fields: `id`, `degreeId`, `startYear`, `endYear`, `status`.

### 4.2 User, Identity & Authentication

6. **User**: Central identity record across all roles.
   - Fields: `id`, `email`, `passwordHash`, `name`, `role` (enum), `isActive`, `isVerified`, `collegeId`, `departmentId`, `companyId`, `createdAt`, `updatedAt`.
   - Roles: `SUPER_ADMIN`, `PLACEMENT_ADMIN`, `PLACEMENT_COORDINATOR`, `DEPARTMENT_COORDINATOR`, `RECRUITER`, `STUDENT`.
7. **Session**: Multi-device refresh token management and revocations.
   - Fields: `id`, `userId`, `refreshToken`, `userAgent`, `ipAddress`, `expiresAt`, `createdAt`.
8. **AuditLog**: Immutable compliance trail for administrative and recruiter actions.
   - Fields: `id`, `userId`, `action`, `entity`, `entityId`, `details` (JSONB), `ipAddress`, `createdAt`.

### 4.3 Student Profile & Portfolio

9. **StudentProfile**: Comprehensive academic and career profile.
   - Fields: `id`, `userId`, `rollNumber`, `registrationNumber`, `gender`, `cgpa`, `tenthPercent`, `twelfthPercent`, `activeBacklogs`, `historyBacklogs`, `placedStatus` (enum), `preferredLocations` (text[]), `createdAt`, `updatedAt`.
10. **StudentSkill**: Many-to-many relationship mapping student to standardized skills.
    - Fields: `id`, `studentProfileId`, `skillId`, `proficiencyLevel` (enum: BEGINNER, INTERMEDIATE, ADVANCED), `verified`.
11. **StudentProject**: Project showcase.
    - Fields: `id`, `studentProfileId`, `title`, `description`, `technologies` (text[]), `repoUrl`, `liveUrl`, `startDate`, `endDate`.
12. **StudentInternship**: Past professional work experience.
    - Fields: `id`, `studentProfileId`, `companyName`, `role`, `description`, `startDate`, `endDate`, `certificateFileKey`.
13. **Certification**: External accreditations (AWS, Google, LeetCode, etc.).
    - Fields: `id`, `studentProfileId`, `title`, `issuingOrg`, `issueDate`, `expiryDate`, `credentialUrl`, `fileKey`.
14. **Resume**: Versioned student resume documents.
    - Fields: `id`, `studentProfileId`, `version`, `title`, `fileKey`, `parsedContent` (JSONB), `isPrimary`, `createdAt`.

### 4.4 Corporate & Job Opportunity Management

15. **Company**: Corporate hiring entity.
    - Fields: `id`, `name`, `industry`, `website`, `logoKey`, `description`, `tier` (enum: MASS, CORE, DREAM, SUPER_DREAM), `createdAt`.
16. **Recruiter**: Recruiter user linked to a company.
    - Fields: `id`, `userId`, `companyId`, `designation`, `workPhone`.
17. **Job**: Specific open position / role.
    - Fields: `id`, `companyId`, `title`, `description`, `jobType` (FULL_TIME, INTERNSHIP, INTERN_PLUS_FTE), `ctcMin`, `ctcMax`, `stipend`, `location`, `openingsCount`, `createdAt`.
18. **PlacementDrive**: Active placement drive organized on campus.
    - Fields: `id`, `collegeId`, `jobId`, `title`, `academicYear`, `driveDate`, `deadlineDate`, `status` (DRAFT, PUBLISHED, REGISTRATION_OPEN, ONGOING, COMPLETED, CANCELLED), `createdAt`.

### 4.5 Eligibility & Placement Rules (Deterministic Engine)

19. **EligibilityRule**: Deterministic criteria executed by the rule engine.
    - Fields: `id`, `placementDriveId`, `minCgpa`, `maxBacklogsAllowed`, `allowedDepartments` (UUID[]), `allowedGenders` (text[]), `minTenthPercent`, `minTwelfthPercent`, `customCriteriaJson` (JSONB).
20. **PlacementPolicy**: College institutional constraints (e.g., "One Student One Job" or "Dream Job Upgrade" policies).
    - Fields: `id`, `collegeId`, `name`, `maxOffersPerStudent`, `dreamOfferPackageMultiplier`, `createdAt`.

### 4.6 Applications, Selection Pipeline & Offers

21. **Application**: Student application for a specific drive.
    - Fields: `id`, `placementDriveId`, `studentProfileId`, `resumeId`, `currentStageId`, `status` (ApplicationStatus enum), `createdAt`, `updatedAt`.
22. **ApplicationStatusHistory**: Immutable event progression audit for an application.
    - Fields: `id`, `applicationId`, `fromStatus`, `toStatus`, `changedByUserId`, `comments`, `createdAt`.
23. **RecruitmentStage**: Sequential hiring stage (e.g., OA -> Round 1 Technical -> HR).
    - Fields: `id`, `placementDriveId`, `stageOrder`, `name`, `stageType` (ONLINE_TEST, TECHNICAL_INTERVIEW, HR_INTERVIEW, GD), `scheduledAt`.
24. **Assessment**: Test scores and proctoring metrics.
    - Fields: `id`, `recruitmentStageId`, `applicationId`, `score`, `percentile`, `status`, `feedback`.
25. **Interview**: Scheduled live interview slot.
    - Fields: `id`, `recruitmentStageId`, `applicationId`, `interviewerUserId`, `scheduledStartTime`, `scheduledEndTime`, `meetingLink`, `status` (SCHEDULED, IN_PROGRESS, COMPLETED, CANCELLED).
26. **InterviewFeedback**: Detailed evaluation rubric submitted by interviewer.
    - Fields: `id`, `interviewId`, `ratingTechnical`, `ratingCommunication`, `ratingProblemSolving`, `overallRating`, `recommendation` (STRONG_HIRE, HIRE, REJECT), `comments`.
27. **Offer**: Formal job offer extended to student.
    - Fields: `id`, `applicationId`, `offeredCtc`, `baseSalary`, `joiningDate`, `offerLetterFileKey`, `status` (PENDING, ACCEPTED, REJECTED, EXPIRED), `validUntil`, `createdAt`.

### 4.7 Skills, Vector Embeddings & AI Models

28. **Skill**: Standardized skill taxonomy (e.g., Python, Docker, React, Distributed Systems).
    - Fields: `id`, `name`, `category`, `normalizedSlug`.
29. **SkillRelationship**: Directed graph of skill affinities (e.g., React implies JavaScript).
    - Fields: `sourceSkillId`, `targetSkillId`, `affinityWeight`.
30. **Embedding**: pgvector store for semantic similarity.
    - Fields: `id`, `entityType` ('RESUME' | 'JOB' | 'SKILL'), `entityId`, `vector` (`vector(384)`), `modelName`, `updatedAt`.
31. **AIAnalysis**: AI extraction cache and skill-gap recommendations.
    - Fields: `id`, `entityType`, `entityId`, `insightsJson` (JSONB), `skillGaps` (text[]), `readinessScore`, `createdAt`.

## 5. Indexing Strategy

- **B-tree Indexes**: On all foreign keys (`collegeId`, `departmentId`, `studentProfileId`, `placementDriveId`).
- **Composite Indexes**: On `[placementDriveId, status]` for lightning-fast application pipeline filtering.
- **Unique Indexes**: On `[placementDriveId, studentProfileId]` preventing duplicate submissions.
- **HNSW / IVFFlat Indexes**: On `vector` column in `Embedding` table for sub-50ms cosine similarity searches (`vector_cosine_ops`).
